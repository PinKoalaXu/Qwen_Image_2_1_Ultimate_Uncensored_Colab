# 参与贡献 / Contributing

欢迎任何人通过 GitHub Fork 和 Pull Request 共同完善本笔记本。公共仓库允许大家提出修改；主分支的修改由维护者审核后合并。

1. Fork 仓库，在自己的分支修改，打开指向 `main` 的 Pull Request。
2. 说明修改原因、涉及组件、依赖版本、测试方式及已知限制。实测时记录 GPU 型号、显存和 Colab 运行环境；没有实测时明确说明。
3. 提交前清空全部单元输出和执行计数，移除附件、令牌、个人路径、私人图片、Gradio 临时链接及其他敏感信息。请使用 GitHub `noreply` 提交邮箱。
4. 新增或替换组件时提供官方来源、准确文件名、许可证及兼容性信息，保留上游署名、NOTICE 和修改说明。不要提交模型权重、无权分发的材料或绕过许可授权的下载方式。
5. 请确认你有权提交修改，并在 PR 中明确同意维护者将这些修改合并到本项目中。不要把独立组件的宽松许可误用于整个模型组合；原创整合内容的其他复用授权仍须向维护者确认。
6. Bugs 和改进建议可使用 Issues；一般交流可使用 Discussions。不要在公开报告中包含私人数据或凭据。

Everyone is welcome to improve this notebook through GitHub forks and pull requests. Changes to the main branch are reviewed and merged by the maintainer.

1. Fork the repository, edit on your own branch, and open a pull request targeting `main`.
2. Explain the problem, changes, affected components, dependency versions, validation, and limitations. Include the GPU, VRAM, and Colab environment for runtime reports; state clearly when a change has not been run.
3. Clear all cell outputs and execution counts before submitting. Remove attachments, credentials, personal paths, private images, temporary Gradio URLs, and other sensitive data. Use your GitHub `noreply` commit email.
4. For new or replacement components, provide upstream sources, exact filenames, licensing, and compatibility information. Preserve attribution, NOTICE files, and change notices. Do not commit weights, unauthorized third-party materials, or downloads that bypass required license authorization.
5. Confirm that you have the right to submit your changes and explicitly permit the maintainer to incorporate them into this project in your PR. A permissive component license does not relicense the combined model. Other reuse permissions for original integration content remain subject to maintainer confirmation.
6. Use Issues for bugs and suggestions, and Discussions for general conversation. Keep private data and credentials out of public reports.
